# 网络设备配置备份与结果可见性 · 工程导读

减少逐台登录华为网络设备导出配置的重复操作，将配置采集、文件留存、浏览下载与通知汇总连接起来。

## 先理解核心流程

```mermaid
flowchart LR
  N0["设备清单"]
  N1["并发 SSH 采集"]
  N2["配置文件落盘"]
  N3["Web 浏览下载"]
  N4["结果通知"]
  N0 --> N1 --> N2 --> N3 --> N4
```

## 值得深入的设计

- ThreadPoolExecutor 按 MAX_WORKERS 并发执行设备采集，并汇总成功、失败和任务耗时。
- 配置文件按设备名与北京时间戳命名，Web 页面按设备名和 IP 筛选并提供下载。
- 采集通过交互式 SSH 发送华为配置命令，设备命令差异和退出条件需要在测试设备上确认。

## 最短运行路线

以下为仓库既有脚本或配置对应的命令。命令以类 Unix Shell 为例，在仓库根目录执行；先准备所需服务和配置，不代表本次文档修改已经完成运行验证。

```bash
cp devices.example.json devices.json
# 编辑设备清单，并替换采集脚本中的通知与访问地址配置
docker build -t network-backup .
docker run -d --name net-backup -p 127.0.0.1:5000:5000 -v "$PWD/backups:/app/backups" network-backup
```

## 一次演示应验证什么

1. Dockerfile 在构建时复制 devices.json，因此必须先准备配置；修改设备清单后需要重新构建或自行配置挂载。
2. 先对一台测试设备验证输出文件包含完整配置，再扩大设备范围。
3. 检查 Web 文件列表和下载结果；确认通知地址与实际可访问地址一致，最后配置周期任务。
